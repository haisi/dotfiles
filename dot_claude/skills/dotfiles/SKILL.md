# Dotfiles (chezmoi)

Everything in `$HOME` (`.zshenv`, `.config/nvim`, `.config/zsh/*`, `.config/i3`, etc.) is
generated by chezmoi from source at `~/.local/share/chezmoi`. The chezmoi binary is on
`PATH` at `~/bin/chezmoi`.

## Golden rule

Never edit a file directly in `$HOME`. It's a generated target — the next `chezmoi apply`
silently overwrites it. Always edit the source file in `~/.local/share/chezmoi` instead.

## Workflow for any dotfile change

1. Find the source for a target path: `chezmoi source-path <target-path>` (e.g.
   `chezmoi source-path ~/.zshenv`), or browse `chezmoi managed` for the full list.
2. Edit the source file in the repo.
3. Apply: `chezmoi apply -v` (prints a diff of what changed).
4. Verify the change actually works (e.g. `zsh -c 'source ~/.zshenv; ...'`, or launch the
   relevant tool headlessly — see the Neovim section below for an example).
5. Commit inside the source repo: `chezmoi git -- add <file>` then
   `chezmoi git -- commit -m "..."`. Only commit when explicitly asked; don't push without
   asking.

A remote is already configured: `github.com/haisi/dotfiles`, tracking `origin/main`. The
local branch is named `master`, so a plain `chezmoi git -- push` fails with an upstream
mismatch — use `chezmoi git -- push origin HEAD:main` instead.

## Naming convention

- `dot_foo` → `~/.foo`
- `private_dot_config/zsh/bar.zsh` → `~/.config/zsh/bar.zsh` (`private_` = 0600 perms)
- Plain names with no leading dot (e.g. `CLAUDE.md`, `README.adoc`) map to `~/CLAUDE.md`,
  `~/README.adoc` unchanged.
- Nested directories only need the `dot_`/`private_` prefix on the first path segment
  that requires it — e.g. `private_dot_config/nvim/lua/plugins/lsp.lua` maps to
  `~/.config/nvim/lua/plugins/lsp.lua` with no further renaming.

## Toolchain and package management

- System packages are declarative via Ansible: edit `dot_bootstrap/setup.yml`, then
  `chezmoi apply` — the `run_onchange_bootstrap.sh.tmpl` script (content-hash-gated)
  reruns the playbook automatically whenever `setup.yml` changes.
- Applying `run_onchange` scripts needs `sudo` in an interactive terminal — this cannot be
  driven non-interactively from an agent's Bash tool. Tell the user to run
  `chezmoi apply -v` themselves (or `! chezmoi apply -v` inside a Claude Code session)
  whenever `setup.yml` changed.
- `mise` (installed via apt) manages per-language runtime versions (currently JDK 25, Node
  LTS) as global defaults — prefer `mise use --global <tool>@<version>` over adding apt
  packages like `nodejs`/`npm` directly, for consistency with the existing pattern.
  `mise activate zsh` is already wired into `.zshrc`, so anything mise-installs is on
  `PATH` in any new shell, including terminals spawned from inside Neovim.
- Tools with no apt package (`zoxide`, `herdr`) install via their own curl-pipe installer
  into `~/.local/bin`, guarded by an `ansible.builtin.stat` check so re-running the
  playbook is a no-op once installed.

## Neovim-specific gotchas

- Config lives at `private_dot_config/nvim/`, using `lazy.nvim`, split one file per
  concern under `lua/config/` (options/keymaps/autocmds/lazy bootstrap) and one file per
  plugin group under `lua/plugins/`.
- `nvim-treesitter` is pinned to the `master` branch on purpose. Its `main` branch is a
  full incompatible rewrite that dropped the `configs.setup()` API and requires Neovim
  0.12+ (nightly). This machine runs stable 0.11.x, and upstream's own README says
  `master` — not `main` — is the branch to use there. If `nvim-treesitter` config ever
  needs touching, keep the branch pin unless Neovim itself gets upgraded to 0.12+.
- Installing/updating Treesitter parsers needs a C compiler (`build-essential`) plus
  `git`/`curl`. LSP servers via `mason-lspconfig`/`mason-tool-installer` mostly need
  `node`/`npm` (via mise) unless they ship a standalone prebuilt binary (`lua_ls`,
  `marksman`, `stylua`, `shfmt` are standalone; `bashls`, `jsonls` need Node).
- To sanity-check a config change without a full interactive session:
  `nvim --headless <file> -c "qa"` and inspect stderr / the exit code for Lua tracebacks.
- Lazy-loaded plugins (`event = {...}`) don't expose their commands until that event
  fires, which headless one-shot invocations often skip. To force-load a plugin and run
  one of its commands non-interactively:
  `nvim --headless -c "lua require('lazy').load({plugins={'<plugin-name>'}})" -c "<Command>" -c "qa"`.
  For treesitter parsers specifically:
  `nvim --headless -c "lua require('lazy').load({plugins={'nvim-treesitter'}})" -c "TSInstallSync! <langs>" -c "qa"`.

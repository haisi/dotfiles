X11 + [i3](https://i3wm.org), with [rofi](https://github.com/davatorium/rofi) as the
launcher and `i3status` for the bar. Bindings follow vim-style `hjkl` for focus and
movement, `$mod` is the Super key, and `$mod+r` opens a resize mode.

```
$mod+Return       → open Ghostty
$mod+d            → rofi launcher
$mod+Shift+x      → i3lock
$mod+hjkl         → focus left/down/up/right
$mod+Shift+hjkl   → move the focused window
$mod+1..0         → switch workspace
$mod+r            → resize mode
```

## The keyboard layout race

i3's config sets the layout on startup:

```
exec --no-startup-id setxkbmap ch de_nodeadkeys
```

But `ibus-daemon` starts a second or so after i3 on every login and applies its own
`preload-engines` XKB layout when its first engine activates — which races
`setxkbmap` and silently overrides it back to `us`. Rather than trying to out-race a
timing-dependent startup order, the bootstrap playbook fixes it at the source: it
reads ibus's `preload-engines` gsetting and, if it isn't already
`['xkb:ch:de_nodeadkeys:deu']`, sets it. Once ibus's own preloaded layout is Swiss
German, there's nothing left for it to race `setxkbmap` over.

See [Laptop function keys](/features/laptop-keys/) for the other thing layered onto
this same i3 config — volume/brightness bindings that only appear on laptop hardware.
